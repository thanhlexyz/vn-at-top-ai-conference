Research directions: Nam Le Hai

Nam Le Hai (HUST) · All professors

Work covers retrieval, distillation and memory for language models, plus benchmarks and datasets for code. Work on retrieval-based context for code generation, conversational memory, cross-lingual question answering, event extraction and few-shot continual relation extraction. Work on benchmarking LLM unit-test generation at repository level across less-studied languages, and on code-understanding benchmarks and large code-text datasets.

Open challenges. Work on graph-based memory and retrieval leaves open computational and memory cost, English-Vietnamese-only evaluation, and relation-extraction overhead. Work on repository-level test generation benchmarks leaves open how to guarantee freedom from data contamination and how to select context adaptively, plus artificial benchmark tasks.

Language models and NLP (6 papers · CSRankings score 0.88)

Topic description

Code generation retrieves context from a knowledge graph spanning a repository and its libraries, with a benchmark for dependency versions. Generative event extraction is distilled into smaller students with event-aware token weighting and span-level relational alignment. Conversational agents get graph memory with turn-level provenance and query-specific retrieval, reaching state-of-the-art memory retrieval on two benchmarks. English-Vietnamese graph retrieval-augmented generation raises retrieval accuracy and generation quality on five cross-lingual benchmarks. Few-shot continual relation extraction uses orthogonal class prototypes and label-description contrastive learning, outperforming prior methods on two benchmarks. Few-shot continual relation extraction keeps pretrained knowledge by maximising mutual information through the language-model head.

Papers (6)
Beyond Repository Boundaries: Cross-Repository Graph Retrieval for Code Generation EMNLP 2026 · rejected
The problem
Repository-level code generation must be compatible with the repository and its dependency environment. Existing retrieval methods mostly use the local repository and one-hop evidence, leaving external API use to pretrained knowledge, which may fail for unseen or version-specific APIs.
The idea
CrossCoder builds a unified knowledge graph over repository and library entities, identifies important nodes via planning and semantic retrieval, and selectively expands neighbours for multi-hop context. The paper also introduces VersionExec, an execution-based benchmark derived from BigCodeBench for dependency versions.
Strengths
On RepoExec, DevEval and VersionExec, the abstract reports improved functional correctness (up to 6.3% pass@1) and robustness to dependency-version changes. Ablations show removing planning gives the largest drop. Rejected from EMNLP 2026.
What the authors leave open
  • The implementation and evaluation focus on the Python ecosystem; other languages may need dedicated structural parsers such as AST libraries or compiler front-ends.
  • Building and indexing multi-hop cross-repository graphs adds computational and memory overhead, especially for large repositories with deep dependency chains; the authors plan to explore knowledge distillation to reduce it.
  • Future work includes using higher-level repository intent from documentation.

EventKD: Event-Aware Knowledge Distillation for Generative Event Extraction EMNLP 2026 · rejected
The problem
LLM-based generative event extraction (triggers, event types, arguments) is costly, so it is distilled into smaller students. Existing KD methods work at the token level and neither focus on event-relevant spans nor capture relations among event components.
The idea
EventKD is a two-level framework: a token-level divergence loss with event-aware span importance weighting, and a span-level Relational-Aware loss preserving pairwise geometry among event spans across Transformer layers.
Strengths
On ACE05, MAVEN, GENEVA and RAMS, the abstract reports EventKD outperforming existing distillation methods on trigger identification and argument extraction. Rejected from EMNLP 2026.
What the authors leave open
  • Span-level alignment alone cannot resolve cases where the teacher gives no disambiguating signal across nearly co-located spans; addressing it would likely need explicit coreference or position-aware objectives.
  • Extension to low-resource languages and other downstream domains is left to future work.

MemORAI: Memory Organization and Retrieval via Adaptive Graph Intelligence for LLM Conversational Agents ACL 2026 · rejected
The problem
LLM conversational agents lack persistent memory for long-term personalised conversations, and the paper states that existing graph-based memory systems dilute information, do not track where facts came from, and retrieve the same way regardless of the query.
The idea
MemORAI filters and compresses memories to keep user-persona content, stores them in a multi-relational graph that records the conversation turn each fact came from, and retrieves query-specific subgraphs with a Dynamic Weighted PageRank whose edge weights depend on the query.
Strengths
The paper reports state-of-the-art memory retrieval and personalised response generation on the LOCOMO and LongMemEval benchmarks.
What the authors leave open
  • Reliance on turn-level provenance and static entity linking may limit adaptability when user intent shifts abruptly or coreferences span many sessions with few explicit mentions.
  • Running large LLMs and complex graph retrieval in real time has high computational and memory cost, which limits use in resource-constrained environments.
  • Future work plans to deploy MemORAI with small language models and small embedding models trained by knowledge distillation while keeping personalised memory retrieval quality.

MaGiX: A Multi-Granular Adaptive Graph Intelligence Framework for Enhancing Cross-Lingual RAG EMNLP 2025 · rejected
The problem
Graph-based retrieval-augmented generation (GRAG) systems such as GraphRAG, LightRAG and HippoRAG2 ground LLM answers in knowledge graphs, but the paper states they are underexplored across languages and limited in semantic granularity and entity alignment.
The idea
MaGiX builds an English–Vietnamese knowledge graph with fine-grained attribute descriptions and cross-synonym edges between entities in the two languages, trains a multilingual embedding model with contrastive learning, and reranks retrieved passages with a semantic-aware composite score.
Strengths
The paper reports higher retrieval accuracy and generation quality than prior GRAG systems on five cross-lingual benchmarks, with the fine-tuned embedding version best on MuSiQue and PopQA.
What the authors leave open
  • With fine-tuned embeddings, performance drops slightly on NQ, which the authors attribute possibly to noise in the synthetic fine-tuning data or to fine-tuning favouring complex cross-lingual patterns.
  • The framework is built for English–Vietnamese question answering and its evaluation is limited to that setting.

Mitigating Non-Representative Prototypes and Representation Bias in Few-Shot Continual Relation Extraction ACL 2025 · accepted
The problem
Few-shot continual relation extraction (FCRE) learns new relation types from a handful of examples without forgetting old ones, and the paper states that with similar classes and few samples, class prototypes are unrepresentative and representations are biased.
The idea
Minion builds class prototypes on a General Orthogonal Frame, a structure motivated by Neural Collapse that keeps classes well separated without a preset number of classes, and uses label-description embeddings as global class representatives in fast-slow contrastive learning.
Strengths
The paper reports that Minion outperforms state-of-the-art methods on two FCRE benchmarks, with ablations for each component.
What the authors leave open
  • Minion adds computational overhead, and its label-description contrastive learning component is more expensive than the prototype component.

Preserving Generalization of Language models in Few-shot Continual Relation Extraction EMNLP 2024 · accepted
The problem
Few-shot Continual Relation Extraction (FCRE) requires models to integrate new relations from limited labeled data while avoiding catastrophic forgetting and preserving the knowledge in pretrained backbones.
The idea
The method uses the often-discarded language model heads through a mutual information maximization strategy to maintain prior knowledge from the pretrained backbone and align the primary classification head. The paper also explores Large Language Models for FCRE.
Strengths
The authors report that the method, which uses language model heads through mutual information maximization, performs well in comprehensive experiments, and that they also evaluate Large Language Models on FCRE.

Datasets, benchmarks, evaluation (3 papers · CSRankings score 0.45)

Topic description

Evaluating LLM unit test generation mostly in standalone settings and a narrow set of languages overestimates real-world readiness. A repository-level benchmark for five less-studied languages, with containerized execution and file-level, language-server-based and retrieval-based context, evaluates 14 LLMs and adds a metric checking whether generated tests exercise the intended functionality. A multiple-choice benchmark of nearly 20,000 questions on code understanding and reasoning, spanning code analysis, defect detection, code repair and execution reasoning, shows that even state-of-the-art models struggle. An open-source dataset of 43 million code-text pairs, extracted with rules and deep learning and released with cleaning scripts, improves several code models over other datasets.

XRepoTest: Benchmarking Multilingual Repository-Level Unit Test Generation for Large Language Models EMNLP 2026 · accepted
The problem
LLM unit-test generation is mostly evaluated in standalone settings and a narrow set of languages, which the abstract says overestimates real-world readiness.
The idea
XRepoTest is a repository-level benchmark for Rust, Go, Julia, PHP and Ruby, using containerised execution and file-level, LSP-based and retrieval-based context. It introduces Invocation Rate (IR) to check whether tests exercise the intended functionality.
Strengths
Experiments with 14 LLMs reveal a substantial gap between standalone and repository-level performance and trade-offs between richer context and test reliability. Accepted at EMNLP 2026.
What the authors leave open
  • The authors plan future work on GraphRAG-based context, adaptive context selection and language-aware augmentation.
  • Data contamination is acknowledged; the authors mitigate and characterise it, for example with temporal filtering, rather than claiming strict guarantees.

CodeMMLU: A Multi-Task Benchmark for Assessing Code Understanding & Reasoning Capabilities of CodeLLMs ICLR 2025 · accepted
The problem
Code LLM research focuses on open-ended code generation and largely overlooks code understanding and reasoning.
The idea
A multiple-choice benchmark of nearly 20,000 questions across several programming languages, covering code analysis, defect detection, software engineering principles, code repair, execution reasoning and fill-in-the-blank tasks.
Strengths
Reports that even state-of-the-art models struggle, showing gaps in comprehension beyond generation; performance on it is not always consistent with code generation benchmarks.
Questions raised by reviewers
  • The questions for the 'real world tasks', e.g., for defect detection or line completion, are very artificial
  • It is unclear to what extent the LLMs were exposed to the underlying resources for this new data set (leakage). This risk is not discussed nor mitigated.
  • Although the issue is acknowledged, unfortunately, no strategies for eliminating this bias are provided.
  • The quality of these generated distractors should be discussed.

The Vault: A Comprehensive Multilingual Dataset for Advancing Code Understanding and Generation EMNLP 2023 · rejected
The problem
Training code language models requires large collections of high-quality code-text pairs in many programming languages.
The idea
An open-source dataset of 43 million code-text pairs, extracted using both rules and deep learning to ensure pair quality, released with cleaning scripts and a framework for replication.
Strengths
Reports that CodeT5, CodeBERT and CodeGen trained on it outperform the same models trained on other datasets such as CodeSearchNet, on code generation, summarization and search.
